ClauseGuard

A contract compliance and risk extraction agent for commercial legal documents.

This project is under active development. The repository link above reflects current progress. The live demo link will be added once the application is deployed.

Overview

Organizations that manage large volumes of vendor and customer contracts rely on legal and compliance teams to manually review terms such as liability caps, indemnification, and termination conditions. This review process is slow and difficult to scale.

ClauseGuard ingests a contract, extracts and classifies key clauses, and flags deviations from a configurable acceptable policy. Every extracted claim is grounded in the exact source text it was drawn from, so a reviewer can verify a finding in seconds rather than rereading the full document. The system is built and evaluated on the Contract Understanding Atticus Dataset (CUAD), a set of over 500 commercial contracts with more than 13,000 expert clause annotations, which serves as ground truth for measuring extraction accuracy.

How It Was Built

  1. Data ingestion
    The CUAD dataset is parsed into a Postgres schema of contracts and clause labels, restricted to ten target clause categories, with a repeatable seed script.
  2. Chunking and embedding
    Contract text is split into paragraph level chunks with exact character offsets preserved, then embedded with a legal domain model and stored in pgvector for retrieval.
  3. Clause extraction
    Claude performs structured tool use extraction across the ten target categories. Output is validated against a shared Zod schema and stored with source character offsets, so every claim traces back to an exact span in the document.
  4. Risk policy engine
    A YAML configurable rule set defines acceptable ranges per clause type. Extracted clauses are compared against policy and flagged by severity when they deviate.
  5. Evaluation harness
    Extraction output is scored against CUAD expert labels for precision, recall, and F1 per clause category, along with hallucination rate and abstention accuracy.
  6. Dashboard
    A Next.js interface for uploading contracts, reviewing source text alongside highlighted clauses, viewing risk flags, and tracking evaluation metrics.

Key Features

Grounded citations

Every extracted clause maps to an exact character span in the source document. If a claim cannot be grounded, the system abstains rather than guess.

Quantified accuracy

Extraction quality is measured against CUAD expert labels using precision, recall, F1, hallucination rate, and abstention accuracy, not qualitative review alone.

Configurable risk policy

Acceptable ranges per clause type are defined in YAML, so compliance rules can be updated without changing application code.

Domain specific retrieval

A legal domain embedding model combined with exact clause type matching supports hybrid retrieval over long contract documents.

Type safe pipeline

Shared Zod schemas enforce a single source of truth for data shapes across ingestion, extraction, and the API layer.

Single language stack

A TypeScript monorepo across frontend, backend, and shared packages keeps the system consistent and straightforward to reason about.
